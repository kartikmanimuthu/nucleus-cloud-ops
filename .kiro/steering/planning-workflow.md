# Planning Workflow

A detailed, structured approach to task execution with comprehensive planning before implementation.

## Before Every Task (Planning Phase)

Before writing ANY code, you MUST:

1. **Understand the task** — Restate what the user is asking in your own words
2. **List affected files** — Enumerate every file you plan to create, modify, or delete
3. **Describe the approach** — Explain the implementation strategy, key decisions, and trade-offs
4. **Identify risks** — Flag any potential side effects, breaking changes, or dependencies
5. **Wait for approval** — Explicitly ask "Shall I proceed?" and do NOT write code until confirmed

---

## After Every Task (Summary Phase)

1. **What was implemented** — A clear description of the feature/fix in plain language
2. **Files changed** — List every file modified with a one-line reason for each
3. **How it works** — Explain the technical flow
4. **How to test it** — Provide exact steps or commands to verify
5. **What to watch out for** — Any caveats, limitations, or follow-up tasks
