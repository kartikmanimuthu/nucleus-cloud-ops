<!-- PostgreSQL target schema (Prisma models to define): -->

Tenants table (parent entity, needed for FK):
- id: String @id @default(cuid())
- name: String (human-readable name)
- createdAt: DateTime @default(now())
- updatedAt: DateTime @updatedAt

TenantConfig table (the entity being migrated from DynamoDB):
- id: String @id @default(cuid())
- tenantId: String (FK → tenants.id, but also plain string for DynamoDB compat)
- configKey: String
- data: Json (stores arbitrary config payload, matches DynamoDB "data" field)
- updatedAt: DateTime @updatedAt
- updatedBy: String @default("system")
- Unique constraint: [tenantId, configKey]
- Index on tenantId for list queries
</interfaces>

Write `prisma/schema.prisma` at the repository root:

```prisma
// This is your Prisma schema file,
// learn more about it in the docs: https://pris.ly/d/prisma-schema

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

// Tenants — parent entity for all multi-tenant data
// Mirrors the TENANT#<tenantId> PK namespace from DynamoDB
model Tenant {
  id        String   @id @default(cuid())
  name      String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  configs TenantConfig[]

  @@map("tenants")
}

// TenantConfig — migrated from DynamoDB APP_TABLE (PK=TENANT#<id>, SK=CONFIG#<key>)
// Each row is one config key-value pair per tenant
model TenantConfig {
  id         String   @id @default(cuid())
  tenantId   String
  configKey  String
  data       Json
  updatedAt  DateTime @updatedAt
  updatedBy  String   @default("system")

  tenant Tenant @relation(fields: [tenantId], references: [id], onDelete: Cascade)

  @@unique([tenantId, configKey])
  @@index([tenantId])
  @@map("tenant_configs")
}
```
