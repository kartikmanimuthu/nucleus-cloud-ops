Per D-01 and D-02: Replace every `getPrismaClient()` call with `getTenantClient(tenantId)` in InventoryPostgresRepository.

1. Change import: `import { getPrismaClient, getTenantClient } from '@/lib/db/pg-config'` (keep getPrismaClient — needed for account lookup in step 7).

2. For methods that already receive `tenantId` as a parameter (`getResource`, `getResourceCounts`, `deleteResourcesByAccount`, `searchByVector`): replace `getPrismaClient()` with `getTenantClient(tenantId)`.

3. For `listResources(filters)`: the `tenantId` is already in `filters.tenantId` — use `getTenantClient(filters.tenantId)`.

4. For `searchByVector`: this uses `$queryRawUnsafe` which is NOT intercepted by the tenant middleware (per D-02 in pg-config.ts). The raw SQL already has `WHERE "tenantId" = $2` — this is correct. BUT still switch the client to `getTenantClient(tenantId)` for consistency, even though raw SQL bypasses the middleware. The explicit WHERE clause in the SQL handles scoping.

5. Per D-03/D-04 (Lambda write path — CRITICAL): Implement account→tenantId lookup INSIDE `upsertResource()` and `upsertBatch()`. The discovery Lambda calls these methods with an `accountId` but may pass a stale or missing `tenantId`. The repository must be the safety net.

   **For `upsertResource(resource)`:**
   - If `resource.tenantId` is already set and non-empty, use it directly: `getTenantClient(resource.tenantId)`.
   - If `resource.tenantId` is falsy OR equals `'default'` OR equals `'org-default'`, resolve it from the account:
     ```typescript
     const account = await getPrismaClient().account.findFirst({
       where: { accountId: resource.accountId },
       select: { tenantId: true }
     });
     if (!account?.tenantId) {
       console.error(`InventoryRepo: No account found for accountId=${resource.accountId}, skipping upsert`);
       return null as unknown as InventoryResource; // Skip write — never write with null tenantId
     }
     const resolvedTenantId = account.tenantId;
     ```
   - Use `getTenantClient(resolvedTenantId)` for the actual upsert. Also set `resource.tenantId = resolvedTenantId` in the data payload so the record is written with the correct tenantId.
   - Note: The account lookup uses `getPrismaClient()` (not tenant-scoped) because this is a cross-entity lookup — acceptable per Claude's Discretion in CONTEXT.md.

   **For `upsertBatch(resources)`:**
   - Guard: if `resources.length === 0` return 0 (already handled).
   - Before the transaction, resolve tenantId for the batch. All resources in a batch share the same accountId (they come from the same discovery scan). Extract `accountId` from `resources[0].accountId`.
   - If `resources[0].tenantId` is falsy OR equals `'default'` OR equals `'org-default'`, do the same account lookup as above.
   - If no account found → log error and return 0 (skip entire batch).
   - Set `resolvedTenantId` on every resource in the array before writing.
   - Use `getTenantClient(resolvedTenantId)` for the `$transaction` call.

6. For all other read methods that already receive explicit `tenantId` params: straightforward `getTenantClient(tenantId)` swap.
