## Screen Inventory

### 1. Custom Roles Settings Page

Route: `/app/settings/roles` (new sub-page under existing settings layout)

Layout:
- Settings sidebar (existing layout from `app/app/settings/layout.tsx`) — add "Roles" nav item
- Main content: page heading + "Create Role" button (top-right) + roles list

Primary focal point: the "Create Role" button in the top-right of the content area.

Roles list structure:
- Predefined roles section (Owner, Admin, Member, Viewer): read-only cards, no edit/delete controls
- Custom roles section: editable cards, each with Edit and Delete icon buttons
- Max 10 custom roles — when limit reached, "Create Role" button is disabled with tooltip "Maximum 10 custom roles reached"

Role card anatomy:
- Role name (heading weight)
- Role level badge (maps to closest predefined level)
- Permission summary: comma-separated list of modules with any access (e.g., "Accounts, Schedules, Inventory")
- Edit button (Pencil icon, ghost variant) — visible only on custom roles; `aria-label="Edit {role name}"`
- Delete button (Trash2 icon, ghost variant, destructive color) — visible only on custom roles; `aria-label="Delete {role name}"`

### 2. Create / Edit Custom Role Dialog

Trigger: "Create Role" button or Edit icon on a custom role card.

Dialog content:
- Title: "Create Custom Role" or "Edit Role: {name}"
- Role name input (required, max 50 chars)
- Permission matrix (Table component):
  - Column headers: Create, Read, Update, Delete
  - Row headers: Accounts, Schedules, AI Ops, Inventory, Settings
  - Each cell: Checkbox
  - Read column always enabled (cannot uncheck Read if any other action is checked — enforced client-side)
- Footer: "Discard Changes" (outline) + "Save Role" (primary) buttons

Validation:
- Role name required, unique within tenant
- At least one permission must be checked
- Inline error below name input on submit if name is taken: "A role with this name already exists"

### 3. Delete Role Confirmation

Component: `AlertDialog`

Copy:
- Title: "Delete {role name}?"
- Body: "Users assigned this role will be downgraded to Viewer. This cannot be undone."
- Cancel: "Keep Role"
- Confirm: "Delete Role" (destructive button variant)

### 4. 403 Forbidden State

Shown inline when an API route returns 403 (existing pattern — use `Alert` component with destructive variant).

Copy:
- Heading: "Access denied"
- Body: "You don't have permission to perform this action. Contact your admin if you think this is a mistake."

## Interaction Contract

### Permission Matrix Rules (client-side enforcement)

1. Checking Create, Update, or Delete on a module auto-checks Read for that module.
2. Unchecking Read on a module auto-unchecks all other actions for that module.
3. Predefined role cards are fully read-only — no checkboxes rendered, permissions shown as text badges.

### Role Assignment Hierarchy (UI enforcement)

- Role selector dropdowns (invite flow, role change) filter options to roles at or below the current user's level.
- Owner sees all roles. Admin sees Admin/Member/Viewer + custom roles at Admin level or below. Member sees no role selector (cannot assign).
- Disabled options are hidden entirely (not shown as disabled) to avoid confusion.

### Disabled State

- "Create Role" button: disabled + tooltip when 10 custom roles exist.
- Save button in dialog: disabled until form is valid (name filled + at least one permission checked).
- Predefined role cards: no edit/delete controls rendered (not disabled — simply absent).
