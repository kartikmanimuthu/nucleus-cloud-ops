<objective>
Fix invited users being unable to log in with their temporary credentials.

Purpose: The D-04 new-user invitation path calls AdminCreateUser in Cognito but never creates an AuthUser row in PostgreSQL. The CredentialsProvider authorize() does `prisma.authUser.findUnique({ where: { email } })` and returns null (→ 401) when no row exists. The acceptPendingInvitation tenant-linking flow never fires because login fails first.

Output: Modified invitation-service.ts that creates an AuthUser record with a hashed temporary password before calling AdminCreateUser, so the Cognito email and the PostgreSQL credentials are in sync.


   ```typescript
   await globalPrisma.authUser.create({
       data: {
           email,
           passwordHash,
       },
   });
   ```

4. Pass `TemporaryPassword` to `AdminCreateUserCommand` so Cognito sends the same password in the email:
   ```typescript
   new AdminCreateUserCommand({
       UserPoolId: COGNITO_USER_POOL_ID,
       Username: email,
       TemporaryPassword: tempPassword,
       UserAttributes: [
           { Name: "email", Value: email },
           { Name: "email_verified", Value: "true" },
       ],
       DesiredDeliveryMediums: ["EMAIL"],
   })
   ```

The AuthUser.create must come BEFORE the Cognito call so that if Cognito fails, we don't have an orphaned AuthUser. Wrap both in a try/catch that deletes the AuthUser if AdminCreateUser throws:

```typescript
await globalPrisma.authUser.create({ data: { email, passwordHash } });
try {
    await getCognitoClient().send(new AdminCreateUserCommand({ ... TemporaryPassword: tempPassword ... }));
} catch (err) {
    // Roll back AuthUser creation if Cognito call fails
    await globalPrisma.authUser.delete({ where: { email } }).catch(() => {});
    throw err;
}
```
