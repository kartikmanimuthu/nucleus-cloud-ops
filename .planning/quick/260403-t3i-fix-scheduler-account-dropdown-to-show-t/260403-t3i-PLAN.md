Root cause summary:
1. `AccountDynamoRepository.getAccounts()` queries GSI1 with `gsi1pk = TYPE#ACCOUNT` — returns ALL tenants' accounts. The `tenantId` passed in filters is never used. Each DynamoDB item has a `tenantId` field — filter in-memory after fetch.
2. `ScheduleDynamoRepository.getSchedules()` same problem — queries GSI1 globally, `tenantId` in filters is destructured but never applied.
3. `create-schedule-dialog.tsx` renders a hardcoded `mockAccounts` array (3 fake accounts). It never calls `/api/accounts`. Also, the `handleSubmit` does NOT include `accountId` in the `createSchedule` payload, which causes the API to return 400 ("Account ID is required").
</context>

  Actually the cleaner fix: the DynamoDB items have `tenantId` stored as an attribute. But `transformToUIAccount` doesn't expose it. The simplest correct fix is to filter `allAccounts` by checking the raw items before transform. Refactor the loop to keep raw items, filter by `tenantId`, then transform:

  Replace the do/while accumulation to collect raw items first:
  ```ts
  let rawItems: Record<string, unknown>[] = [];
  // ... do/while pushes fetchResponse.Items into rawItems ...

  Then remove the `let filteredAccounts = allAccounts;` line and update the subsequent filters to operate on `filteredAccounts` directly (they already do via reassignment — just ensure the variable name is consistent).

  if (!open) return;
  setLoadingAccounts(true);
  fetch('/api/accounts')

            id: a.accountId,
            name: a.name,
            accountId: a.accountId,
          }))
        );
      }
    })
    .catch(console.error)
    .finally(() => setLoadingAccounts(false));
}, [open]);
```
