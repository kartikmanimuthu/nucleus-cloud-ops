<objective>
Remove all DynamoDB dependencies from the agent-ops module and migrate scheduled task execution from in-process croner to pg-boss.

Purpose: The agent-ops module still has stale DynamoDB references in comments and uses an in-process croner scheduler (scheduler-engine.ts) that doesn't survive container restarts and can't coordinate across ECS instances. pg-boss provides durable cron scheduling with PostgreSQL-backed persistence, consistent with the scheduler and discovery workers.

Output: Clean agent-ops module with zero DynamoDB references and pg-boss-based scheduled task execution.
</objective>

    **A. Create `workers/src/jobs/agent-ops-scheduler/index.ts`:**
    - Export `register(boss: PgBoss)` function following the existing worker pattern.
    - Create queue `agent-ops-task-tick` with stately policy (prevents duplicate runs).
    - On startup, query PostgreSQL for all active scheduled tasks (`SELECT * FROM agent_ops_scheduled_tasks WHERE task_status = 'active' AND deleted_at IS NULL`). For each, call `boss.schedule()` with the task's cronExpression and timezone.
    - Register a work handler that: acquires execution lock via `tryAcquireExecutionLock`, creates a run via the agent-ops service, and fires the trigger API endpoint (`POST /api/agent-ops/scheduled-tasks/{taskId}/trigger`) via internal HTTP call to `http://localhost:${process.env.PORT || 3000}` (same pattern as the web-ui container). Alternatively, if the LangGraph dependencies are too heavy for workers, use `boss.send()` from the work handler to a queue that web-ui consumes — but prefer the HTTP trigger approach for simplicity.
    - Also create queue `agent-ops-task-manage` for schedule management (register/unregister/update). Register a work handler that processes schedule changes.
    - Use `createLogger('agent-ops-scheduler')` from `workers/src/lib/logger.ts` for all logging.

    **B. Rewrite `web-ui/lib/agent-ops/scheduler-engine.ts`:**
    - Remove croner dependency entirely. Remove the globalThis singleton pattern.
    - `registerTask(task)`: Call `getBoss()` then `boss.schedule('agent-ops-task-tick', task.cronExpression, { taskId: task.taskId, tenantId: task.tenantId }, { tz: task.timezone })`. Use `singletonKey: task.taskId` to allow unschedule.
    - `unregisterTask(taskId)`: Call `getBoss()` then `boss.unschedule('agent-ops-task-tick:${taskId}')` or equivalent pg-boss API to remove the schedule for that task.
    - `initializeScheduler()`: Remove — workers handle startup registration now. Keep as no-op or remove entirely and update callers.
    - `shutdownScheduler()`: Remove — pg-boss handles cleanup.
    - Keep the same export signatures so API routes don't need import changes.

    **C. Update API routes** (minimal changes — `registerTask`/`unregisterTask` signatures stay the same):
    - `scheduled-tasks/route.ts` POST: `registerTask(task)` already called — now goes through pg-boss instead of croner. No change needed if export signature preserved.
    - `[taskId]/route.ts` PATCH/DELETE: Same — `registerTask`/`unregisterTask` calls stay.
    - `[taskId]/pause/route.ts`: `unregisterTask` call stays.
    - `[taskId]/resume/route.ts`: `registerTask` call stays.
    - `[taskId]/trigger/route.ts`: No change — this is the execution endpoint the worker calls.

    **D. Register in `workers/src/index.ts`:**
    - Add `import { register as registerAgentOpsSchedulerJobs } from './jobs/agent-ops-scheduler/index.js';`
    - Call `await registerAgentOpsSchedulerJobs(boss);` after existing registrations.

    **Key design decisions:**
    - Queue name per task: `agent-ops-task-tick:{taskId}` (allows per-task unschedule, matches scheduler pattern `scheduler-scan:{tenantId}`).
    - Worker triggers execution via HTTP POST to the existing trigger endpoint — keeps LangGraph execution in web-ui process where all agent dependencies live.
    - Execution lock (`tryAcquireExecutionLock`) already exists in scheduled-task-service — worker should use it to prevent duplicate runs across instances.
