1. Adds a `search_vector tsvector` column to `inventory_resources` (nullable, no default — trigger handles population).

2. Creates a trigger function `inventory_search_vector_update()` that builds the tsvector from multiple fields:
   ```sql
   CREATE OR REPLACE FUNCTION inventory_search_vector_update() RETURNS trigger AS $$
   BEGIN
     NEW.search_vector :=
       setweight(to_tsvector('english', coalesce(NEW.name, '')), 'A') ||
       setweight(to_tsvector('english', coalesce(NEW."resourceType", '')), 'B') ||
       setweight(to_tsvector('english', coalesce(NEW."resourceId", '')), 'B') ||
       setweight(to_tsvector('english', coalesce(NEW.region, '')), 'C') ||
       setweight(to_tsvector('english', coalesce(NEW.status, '')), 'C') ||
       setweight(to_tsvector('english', coalesce(NEW.tags::text, '')), 'C') ||
       setweight(to_tsvector('english', coalesce(NEW.metadata::text, '')), 'D');
     RETURN NEW;
   END
   $$ LANGUAGE plpgsql;
   ```
   Use weighted tsvector: A=name, B=resourceType+resourceId, C=region+status+tags, D=metadata (full JSON blob).

3. Creates a BEFORE INSERT OR UPDATE trigger on `inventory_resources` that calls this function.

4. Creates a GIN index: `CREATE INDEX idx_inventory_search_vector ON inventory_resources USING GIN (search_vector);`

5. Backfills existing rows: `UPDATE inventory_resources SET search_vector = ... (same expression)` so existing data is immediately searchable.
