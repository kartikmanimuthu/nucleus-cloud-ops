## Root Cause

`withAuth` middleware calls `getToken()` which decodes the `next-auth.session-token` cookie as a JWT.
With `strategy: "database"`, that cookie holds an **opaque UUID** (not a JWT) — so `getToken()` returns
`null`, `authorized()` returns `false`, and every protected route (`/app/*`) redirects to signin,
creating an infinite loop.

The credentials 401 is a separate symptom: the `authorize` function returns `null` for Cognito-only
users (no `passwordHash`), which NextAuth maps to a 401 with `CredentialsSignin` error.

## Fix

Switch `session.strategy` from `"database"` to `"jwt"`. With JWT strategy:
- The session cookie IS a signed JWT — `getToken()` decodes it correctly
- `withAuth` middleware works as intended
- The `jwt` callback (already written) enriches the token with `tenantId`/`role`/`isSuperAdmin`
- The `session` callback must be updated to read from `token` (not `user`)
- Invitation acceptance logic must move from `session` callback → `jwt` callback (only runs on sign-in)

The `PrismaAdapter` stays — it's still needed for OAuth account linking (`auth_accounts`, `auth_users`).
The `auth_sessions` table becomes unused (no data loss, just dormant).

## Task 1 — Switch session strategy and fix callbacks

**Files:** `web-ui/lib/auth-options.ts`

**Action:**

1. Change `session.strategy` from `"database"` to `"jwt"`
2. In `jwt` callback: move invitation acceptance logic here (currently in `session` callback).
   Guard with `if (user)` so DB queries only run on initial sign-in, not every request.
   Also set `token.email = user.email` so it's available in the session callback.
3. Replace `session` callback body: read from `token` instead of `user`.

**New `jwt` callback:**
```typescript
async jwt({ token, user }) {
    if (user) {
        const activeTenantId = (user as any).activeTenantId;
        let utr;
        if (activeTenantId) {
            utr = await prisma.userTenantRole.findFirst({
                where: { userId: user.id, tenantId: activeTenantId },
            });
        }
        if (!utr) {
            utr = await prisma.userTenantRole.findFirst({
                where: { userId: user.id },
            });
        }
        // D-14: Accept pending invitations on first login with no tenant
        if (!utr) {
            try {
                const { InvitationService } = await import("@/lib/invitation-service");
                await InvitationService.acceptPendingInvitation(user.id, user.email ?? "");
                utr = await prisma.userTenantRole.findFirst({
                    where: { userId: user.id },
                });
            } catch (err) {
                console.error("jwt callback: acceptPendingInvitation failed:", err);
            }
        }
        token.tenantId = utr?.tenantId ?? null;
        token.role = utr?.role ?? null;
        token.isSuperAdmin = (user as any).isSuperAdmin ?? false;
        token.email = user.email;
    }
    return token;
},
```

**New `session` callback:**
```typescript
async session({ session, token }) {
    session.user = {
        id: token.sub as string,
        email: (token.email as string) ?? "",
        tenantId: (token.tenantId as string | null) ?? null,
        role: (token.role as string | null) ?? null,
        isSuperAdmin: (token.isSuperAdmin as boolean) ?? false,
    };
    return session;
},
```

**verify:** After change, `npm run build` in `web-ui/` must pass with no type errors.

**done:** `session.strategy` is `"jwt"`, `session` callback uses `token`, `jwt` callback includes invitation logic.

## Task 2 — Improve credentials error for SSO-only users

**Files:** `web-ui/lib/auth-options.ts`, `web-ui/app/login/page.tsx`

**Action:**

In `authorize`, distinguish "user not found" from "user exists but has no password" (Cognito-only):
```typescript
if (!user) return null;
if (!user.passwordHash) {
    throw new Error("This account uses SSO. Please sign in with the SSO tab.");
}
```

In `login/page.tsx`, the existing error handler already passes through non-`CredentialsSignin` errors:
```typescript
result.error === "CredentialsSignin"
    ? "Invalid email or password."
    : result.error   // ← custom thrown message shows here
```
No change needed in the login page — the thrown message will surface automatically.

**verify:** Attempting credentials login for a Cognito-only user shows the SSO message instead of generic error.

**done:** `authorize` throws descriptive error for passwordHash-less users.
