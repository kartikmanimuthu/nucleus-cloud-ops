    **Create `web-ui/components/settings/role-dialog.tsx`:**

    Props:
    ```typescript
    interface RoleDialogProps {
      open: boolean;
      onOpenChange: (open: boolean) => void;
      role?: { id: string; name: string; permissions: PermissionSet } | null; // null = create mode
      onSave: (name: string, permissions: PermissionSet) => Promise<void>;
    }
    ```

    Dialog content per UI-SPEC:
    - Title: "Create Custom Role" when role is null, "Edit Role: {name}" when editing
    - Role name Input (required, max 50 chars, placeholder "e.g., DevOps Lead")
    - Permission matrix using Table component:
      - Column headers: empty cell + "Create" + "Read" + "Update" + "Delete"
      - 5 rows, one per module: "Accounts", "Schedules", "AI Ops", "Inventory", "Settings"
      - Each cell: Checkbox component
      - Minimum row height 44px for accessibility (touch targets)

    State management:
    - `name` string state, initialized from role?.name or ''
    - `permissions` state as `Record<Module, Set<Action>>`, initialized from role?.permissions or empty
    - `saving` boolean for loading state
    - `error` string | null for inline error display

    **Permission matrix interaction rules (per UI-SPEC Interaction Contract):**
    1. When checking Create, Update, or Delete on a module → auto-check Read for that module
    2. When unchecking Read on a module → auto-uncheck Create, Update, Delete for that module
    3. Implementation: in the onChange handler for each checkbox:
       ```typescript
       function togglePermission(module: Module, action: Action) {
         setPermissions(prev => {
           const next = { ...prev };
           const actions = new Set(next[module] || []);
           if (actions.has(action)) {
             actions.delete(action);
             // Rule 2: unchecking Read clears all
             if (action === 'read') {
               actions.clear();
             }
           } else {
             actions.add(action);
             // Rule 1: checking C/U/D auto-checks Read
             if (action !== 'read') {
               actions.add('read');
             }
           }
           next[module] = Array.from(actions) as Action[];
           return next;
         });
       }
       ```

    Footer buttons:
    - "Discard Changes" (outline variant) — calls onOpenChange(false)
    - "Save Role" (primary variant) — disabled until name is non-empty AND at least one permission checked
    - On save: convert permissions state to PermissionSet, call onSave(name, permissions)

    Validation:
    - Name required — show inline error below input if empty on submit
    - At least one permission — show inline error if none checked on submit
    - API error (e.g., "A role with this name already exists") — show below name input

    The onSave callback in the parent page (roles/page.tsx) handles the fetch:
    - Create: POST /api/settings/roles with { name, permissions }
    - Edit: PUT /api/settings/roles/{roleId} with { name, permissions }
    - On success: close dialog, refresh roles list
    - On error: set error state in dialog
