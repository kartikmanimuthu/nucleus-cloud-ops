# Milestone v4.0: Tenant Isolation Hardening

**Status:** ✅ SHIPPED 2026-04-03
**Phases:** 18–21
**Total Plans:** 9

## Overview

Audited and fixed tenant ID integration across all PostgreSQL CRUD operations. Every module now correctly scopes Create, Read, Update, Delete, Search, and Filter by the active tenant. Added regression tests (unit + API-level) to prevent future regressions.

**Core Value:** No cross-tenant data leakage, no missing tenantId on inserts, no unscoped list/filter queries — enforced by `getTenantClient()` across all 10 Postgres repositories and verified by 16 new test files.

## Milestone Summary

**Key Decisions:**

- `getTenantClient(tenantId)` via Prisma `$extends` as the canonical tenant isolation mechanism — auto-injects tenant_id on every query, eliminates risk of missed WHERE clauses
- Pre-flight ownership check in API route layer (not repository) returns 403 before any cross-tenant mutation attempt — explicit and auditable
- Discovery Lambda write path: resolve tenantId from accountId at write time via account table lookup — keeps Lambda stateless
- KnowledgeBaseService wired to repository factory (USE_PG_KB flag) — DynamoDB and Postgres backends interchangeable
- AgentOpsEvent tenantId sourced from run object (not hardcoded 'org-default') — fixed during Phase 19 verification
- Regression tests use vi.mock('@/lib/db/pg-config') to verify getTenantClient called with correct tenantId — no real DB required

**Issues Resolved:**

- AgentOpsEventPostgresRepository was hardcoding `tenantId: 'org-default'` — fixed in Phase 19 gap closure
- KnowledgeBaseService bypassed repository factory entirely (direct DynamoDB calls) — fixed in Phase 20 gap closure
- AuditService call sites across all modules were missing tenantId — swept in Phase 21

**Issues Deferred (v4.1+):**

- Super Admin Panel (ADMIN-01–07) — platform-level admin UI
- Tenant Suspension (SUSP-01–04) — requires database session enforcement
- Raw SQL ($executeRaw) audit — callers must manually scope; not intercepted by getTenantClient hook
- LangGraph thread ID migration (bare UUIDs → tenantId:userId:uuid format)

**Technical Debt:**

- `$executeRaw` / `$queryRawUnsafe` calls are NOT intercepted by the tenant hook — any raw SQL must manually include WHERE tenant_id = $1
- Legacy bare UUID LangGraph threads need migration script before production launch
