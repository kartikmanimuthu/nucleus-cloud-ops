**ScheduledTaskPostgresRepository** — For `tryAcquireExecutionLock`, use raw SQL via Prisma `$executeRaw`:
```typescript
async tryAcquireExecutionLock(taskId: string, scheduledAt: string): Promise<boolean> {
    const expiresAt = new Date(Date.now() + 3600 * 1000);
    try {
        await getPrismaClient().$executeRaw`
            INSERT INTO "scheduled_task_locks" ("id", "taskId", "scheduledAt", "acquiredAt", "expiresAt")
            VALUES (gen_random_uuid(), ${taskId}, ${scheduledAt}, NOW(), ${expiresAt})
            ON CONFLICT ("taskId", "scheduledAt") DO NOTHING
        `;
        // Check if row was inserted (rowCount would be 1 for insert, 0 for conflict)
        const lock = await getPrismaClient().scheduledTaskLock.findUnique({
            where: { taskId_scheduledAt: { taskId, scheduledAt } }
        });
        // If lock exists and was just created (within last second), we acquired it
        return lock !== null && (Date.now() - lock.acquiredAt.getTime()) < 2000;
    } catch {
        return false;
    }
}
```
Actually, a cleaner approach: use `$executeRawUnsafe` and check affected rows, or use a two-step approach with `createMany({ skipDuplicates: true })` and check if the record's acquiredAt matches.

**migrate-kb.ts** — Follow migrate-schedules.ts pattern exactly. Migrates from NucleusAppTable (APP_TABLE_NAME):

1. Query GSI1 with gsi1pk='TYPE#KNOWLEDGE_BASE' to get all KBs
2. For each KB, extract fields: id (from item.id), tenantId, name, description, status, vectorCount, dataSourceCount, createdAt, updatedAt, createdBy
3. Upsert into PostgreSQL knowledge_bases table via Prisma upsert (ON CONFLICT on id)
4. Query PK=KB#<kbId> with SK begins_with DATASOURCE# to get all data sources per KB
5. For each DataSource, extract: id, tenantId (from parent KB), knowledgeBaseId, name, sourceType, status, config (JSON), vectorCount, vectorKeys, lastSyncAt, lastSyncError, createdAt, updatedAt

7. Progress logging: "Migrated X/Y knowledge bases..." and "Migrated X/Y data sources..."

Usage: `AWS_PROFILE=PLATFORM-ADMIN DATABASE_URL=postgresql://... npx tsx scripts/migrate-kb.ts`

Note: DataSource items in DynamoDB have PK=KB#<kbId> (not TENANT#), so tenantId must be looked up from the parent KB record. The script should build a kbId->tenantId map from the KB records first.

**migrate-agent-ops.ts** — Migrates from AgentOpsTable (AGENT_OPS_TABLE_NAME env var):

1. Scan the table (no GSI for all items — use full table scan with FilterExpression or paginated scan)
2. Classify items by SK prefix:
   - SK starts with 'RUN#' → agent_ops_runs
   - SK starts with 'EVENT#' → agent_ops_events
   - SK starts with 'SCHED#' → scheduled_tasks
3. For runs: extract all fields from AgentOpsRun type, compute expiresAt from ttl (epoch -> Date), upsert by (tenantId, runId)
4. For events: extract all fields, compute expiresAt from ttl, need tenantId from parent run (build runId->tenantId map), upsert
5. For scheduled tasks: extract all fields, upsert by (tenantId, taskId)
6. Batch in chunks of 500 with progress logging
7. Idempotent via Prisma upsert

Usage: `AWS_PROFILE=PLATFORM-ADMIN DATABASE_URL=postgresql://... AGENT_OPS_TABLE_NAME=NucleusAgentOpsTable npx tsx scripts/migrate-agent-ops.ts`
