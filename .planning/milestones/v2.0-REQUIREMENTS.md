# Requirements Archive: v2.0 Pulumi IaC Migration

**Milestone:** v2.0
**Archived:** 2026-03-30
**Core Value:** Pulumi TypeScript managing all core AWS infrastructure — CDK removed for NetworkingStack + ComputeStack, WebUIStack stays in CDK

## All Requirements — Final Status

### Foundation

- [x] **PULUMI-01**: Engineer can scaffold the Pulumi project in `infra/` with S3 backend, KMS secrets provider, and two Pulumi projects (`infra/networking/`, `infra/compute/`) — `pulumi preview` runs without error
  - **Outcome:** ✅ Validated — Phase 6. S3 backend live, KMS secrets provider configured, both projects preview without error.

- [x] **PULUMI-02**: Engineer can deploy NetworkingStack via Pulumi: VPC, 4-tier subnets (Public/Private/Database/Intra), NAT gateway, IGW, VPC Gateway Endpoints (S3 + DynamoDB), RDS/ElastiCache subnet groups
  - **Outcome:** ✅ Validated — Phase 7. `nucleus-vpc` deployed (`vpc-0cd6e5fd607d1a494`), all 4 subnet tiers, 2 NAT gateways, S3+DynamoDB gateway endpoints.

- [x] **PULUMI-03**: ComputeStack reads VPC ID and subnet IDs from NetworkingStack via `StackReference.requireOutput()` — no hardcoded IDs
  - **Outcome:** ✅ Validated — Phase 7. `requireOutput()` resolves to live VPC ID at preview time.

### Data Layer

- [x] **PULUMI-04**: Engineer can deploy all 9 DynamoDB tables via Pulumi with correct schemas, GSIs, TTL attributes, and `retainOnDelete: true` protection matching the CDK definitions
  - **Outcome:** ✅ Validated — Phase 8. All 9 tables deployed with correct schemas, GSIs, TTL attributes, `retainOnDelete: true`.

- [x] **PULUMI-05**: Engineer can deploy all 4 S3 buckets via Pulumi with correct lifecycle rules (checkpoint 30d, agent-temp 1d, inventory raw 365d/exports 7d, kb-staging 1d)
  - **Outcome:** ✅ Validated — Phase 8. All 4 buckets with correct lifecycle rules, `retainOnDelete: true`.

- [x] **PULUMI-06**: Engineer can deploy VectorProcessing and KBSync SQS queue pairs with DLQs and a CloudWatch alarm on VectorProcessingDLQ (threshold=1)
  - **Outcome:** ✅ Validated — Phase 8. Both queue pairs with DLQs, CloudWatch alarm active.

- [x] **PULUMI-07**: Engineer can deploy Cognito UserPool, UserPoolDomain, UserPoolClient (with generated secret), and IdentityPool via Pulumi — client secret stored as Pulumi secret output
  - **Outcome:** ✅ Validated — Phase 8. Full Cognito stack deployed, client secret encrypted in Pulumi state.

### Compute — Lambda

- [x] **PULUMI-08**: Engineer can deploy Scheduler Lambda (ARM64, Node 20) via Pulumi with esbuild pre-build step, correct IAM role, EventBridge trigger (every 30 min), and all env vars wired from stack outputs
  - **Outcome:** ✅ Validated — Phase 9. `nucleus-cloud-ops-function` deployed, EventBridge cron rule active.

- [x] **PULUMI-09**: Engineer can deploy VectorProcessor Lambda (ARM64, Node 20) via Pulumi with SQS event source (batchSize=1, maxConcurrency=5) and esbuild pre-build
  - **Outcome:** ✅ Validated — Phase 9. `nucleus-cloud-ops-vector-processor` deployed with SQS trigger.

- [x] **PULUMI-10**: Engineer can deploy KBSyncProcessor Lambda (ARM64, Node 20) via Pulumi with SQS event source (batchSize=1) and esbuild pre-build
  - **Outcome:** ✅ Validated — Phase 9. `nucleus-cloud-ops-kb-sync-processor` deployed with SQS trigger.

- [x] **PULUMI-11**: Engineer can deploy Discovery ECS task definition (ARM64, Python container) via Pulumi with EventBridge Scheduler (daily 2AM UTC) and EventBridge Rule for on-demand `StartDiscovery` events
  - **Outcome:** ✅ Validated — Phase 9 (task def + EventBridge Rule) + Phase 10 (EventBridge Scheduler). Split across phases due to cluster ARN dependency.

### Compute — ECS + ALB + CloudFront

- [x] **PULUMI-12**: Engineer can deploy ECS Fargate cluster and WebUI task definition (ARM64) via Pulumi with all 30+ container env vars wired from stack outputs via `pulumi.all()`
  - **Outcome:** ✅ Validated — Phase 10. `nucleus-cloud-ops-ecs-cluster` deployed, task definition with 50+ env vars via `pulumi.all()`.

- [x] **PULUMI-13**: Engineer can deploy ECS Fargate service via Pulumi with `forceNewDeployment: true`, deployment circuit breaker (enable + rollback), ALB target group, and auto scaling (CPU 70% + Memory 75%)
  - **Outcome:** ✅ Validated — Phase 10. Service deployed with circuit breaker, auto scaling configured.

- [x] **PULUMI-14**: Engineer can deploy ALB with HTTP listener (idleTimeout=1200s) and health check on `/api/health` via Pulumi
  - **Outcome:** ✅ Validated — Phase 10. ALB deployed, health check on `/api/health`.

- [x] **PULUMI-15**: Engineer can deploy CloudFront distribution via Pulumi with ALB origin, caching disabled, and a stable `random.RandomString` origin verify secret (not `crypto.randomBytes`)
  - **Outcome:** ✅ Validated — Phase 10. CloudFront at `https://d11lr8aqp8vqde.cloudfront.net`, `random.RandomString` secret stable.

### Cutover + Cleanup

- [x] **PULUMI-16**: Engineer can run `scripts/generate-env.ts` to read `pulumi stack output --json` and write `web-ui/.env.local` with all required env vars
  - **Outcome:** ✅ Validated — Phase 11. Script created, reads all 49 stack outputs with `--show-secrets`.

- [x] **PULUMI-17**: Engineer can destroy CDK NetworkingStack and ComputeStack after Pulumi stacks are smoke-tested — `lib/networkingStack.ts`, `lib/computeStack.ts`, and `bin/cdkStack.ts` deleted; CDK deps removed for those stacks (WebUIStack and its CDK deps remain)
  - **Outcome:** ✅ Partially validated — Phase 11. Source files deleted, `bin/webUIStack.ts` created, WebUIStack synth verified. CDK stack destruction is manual (user-controlled after production verification).

- [x] **PULUMI-18**: S3 Vectors (2 indexes) and S3 Tables (Iceberg TableBucket) are wrapped in `aws.cloudformation.Stack` resources in the Pulumi compute stack — CFN templates extracted from `cdk synth` output
  - **Outcome:** ✅ Validated — Phase 11. CFN templates extracted, wrapped in `aws.cloudformation.Stack`.
