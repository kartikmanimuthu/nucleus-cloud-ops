# Milestone v2.0: Pulumi IaC Migration

**Status:** ✅ SHIPPED 2026-03-30
**Phases:** 6–11
**Total Plans:** 17

## Overview

Replaced AWS CDK with Pulumi TypeScript for NetworkingStack and ComputeStack. All core AWS infrastructure (VPC, ECS Fargate, ALB, CloudFront, Lambda, DynamoDB, SQS, EventBridge, Cognito, S3) is now managed by Pulumi with an S3 backend and KMS secrets provider. WebUIStack stays in CDK. CDK source files for the migrated stacks deleted from the repo.

## Milestone Summary

**Key Decisions:**

- S3 backend (no DynamoDB lock table) — Pulumi uses S3 conditional writes; DynamoDB lock is a Terraform pattern
- KMS secrets provider — no passphrase; required for CI/team use; passphrase loss locks state permanently
- `@pulumi/aws` primitives only — no `@pulumi/awsx` or `@pulumi/cdk`; CDK parity easier to verify with 1:1 mapping
- Explicit physical names on every resource — Pulumi auto-naming appends 7-char suffix; any rename triggers delete+create
- `retainOnDelete: true` on all DynamoDB tables and S3 buckets — protection against accidental `pulumi destroy`
- `forceNewDeployment: true` on ECS service — ECS does not redeploy on task definition update without this
- Blue/green cutover — Pulumi deploys new resources alongside CDK; CDK stays live until Pulumi smoke-tested
- S3 Vectors + S3 Tables deferred to Phase 11 — no native `@pulumi/aws` support; wrapped in `aws.cloudformation.Stack`
- `awsx.ec2.Vpc` used for networking (exception to `@pulumi/aws` primitives rule) — matches CDK abstraction level
- CDK destruction is manual — user controls timing after Pulumi production verification

**Issues Resolved:**

- KMS URI region suffix (`?region=us-east-1`) — profile default region mismatch with bucket/key region
- StackReference format requires literal `organization` prefix for S3 backend
- `aws.getCallerIdentityOutput()` instead of top-level await — tsconfig commonjs incompatibility
- `aws.lambda.Function` uses `name` not `functionName` — Pulumi API differs from CDK NodejsFunction
- `npm ci` required before esbuild for scheduler Lambda — non-AWS-SDK deps not in Lambda runtime
- databaseSubnetIds/intraSubnetIds filtered by Name tag — vpc.isolatedSubnetIds merges all Isolated tiers

**Issues Deferred:**

- CDK NetworkingStack + ComputeStack destruction — manual, user-controlled after production verification
- S3 Vectors real wiring for VectorProcessor/KBSyncProcessor — placeholder env vars until production cutover
- WebUIStack migration to Pulumi — explicitly out of scope for v2.0
- RDS/Aurora for production PostgreSQL — future milestone
- ECS service desiredCount=0 — scale up after smoke testing

**Tech Debt:**

- `VECTOR_BUCKET_NAME` and `KB_VECTOR_BUCKET_NAME` are placeholder values in Lambda env vars — need real S3 Vectors bucket ARN after CDK destruction
- Discovery task definition cpu=256/memory=512 in Phase 9 (corrected to 1024/2048 in Phase 10 update)
