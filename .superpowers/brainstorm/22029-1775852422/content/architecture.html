Text-to-SQL Agent — Architecture

LangGraph StateGraph with full quality reflection loop

Agent Flow — LangGraph StateGraph
START
→ User question + conversation history + tenantId
↓
describe_schema
Run SELECT column_name, data_type FROM information_schema.columns WHERE table_name = 'inventory_resources' + sample rows. Cached per session.
↓
generate_sql
LLM generates SQL from question + schema + prior errors. Enforces: SELECT only, WHERE tenant_id = $1, LIMIT 500
↓
execute_sql
Raw pg Pool client. Parameterized pool.query(sql, [tenantId]). Read-only transaction. 10s timeout. Returns rows + row count.
↓
reflect
LLM evaluates: "Did this query answer the user's question?"
Checks: SQL errors? Empty results when data expected? Wrong columns? Incomplete answer?
Returns: { satisfied: boolean, feedback: string }
↓
satisfied?
NO → back to generate_sql with feedback (max 3 retries) ↩
YES → continue to synthesize ↓
↓
synthesize
LLM generates natural language answer from query results. Streams to user. Includes data tables, counts, summaries as appropriate.
↓
END
→ Streamed response complete

State Shape

interface TextToSQLState {
  // Input
  question: string;
  conversationHistory: BaseMessage[];
  tenantId: string;
  filters?: { accountIds?: string[]; region?: string; resourceType?: string };

  // Schema (cached after first run)
  schemaDescription: string;
  sampleRows: Record<string, unknown>[];

  // SQL generation loop
  generatedSQL: string;
  sqlResult: { rows: Record<string, unknown>[]; rowCount: number } | null;
  sqlError: string | null;
  reflectionFeedback: string;
  iteration: number;        // current retry count
  maxIterations: number;    // default 3
  satisfied: boolean;

  // Output
  finalAnswer: string;      // streamed to user
}

Key Design Decisions

Raw pg, not Prisma
LLM-generated SQL can't go through an ORM. Direct pg.Pool.query() with parameterized tenantId.
Runtime schema introspection
Query information_schema at runtime instead of hardcoding. Schema stays accurate as migrations evolve.
Tenant isolation enforced
Every generated SQL must include WHERE tenant_id = $1. Validated before execution. Parameterized, never interpolated.
Safety guardrails
SELECT-only validation. Read-only transaction (SET TRANSACTION READ ONLY). 10s query timeout. LIMIT 500 cap.
